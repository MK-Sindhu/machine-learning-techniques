Linear regression, scored by 5-fold cross-validation

He says that in his own work he would not stop at plain linear regression. Ridge and lasso have hyperparameters to tune, so they leave more room to improve. Linear regression comes first only to show the workflow. Import paths need not be memorized; he searches the scikit-learn docs for them too.

Cell · linear regression with cross-validation
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import cross_val_score

lin_regressor = LinearRegression()
mse = cross_val_score(lin_regressor, X, y, scoring='neg_mean_squared_error', cv=5)
print(mse)                   # five values, one per fold
mean_mse = np.mean(mse)
print(mean_mse)              # -37.13...

What cross-validation does

With cv=5 the rows are cut into five equal blocks. Each block takes one turn as the test set while the other four train the model, so there are five train/test combinations and five scores. With 100 records, each test block holds 20 records and each training set 80. cross_val_score returns the five scores, and their mean is the model's cross-validation score. He keeps the explanation short and offers a separate session on it later.

\[ \text{MSE}_j = \frac{1}{m_j}\sum_{i \in \text{fold } j}\big(y_i - \hat y_i\big)^2, \qquad \text{CV score} = \frac{1}{5}\sum_{j=1}^{5}\big(-\text{MSE}_j\big) \]

Here he passes the whole of X and y. He points out the better practice: do the train/test split first and cross-validate only the training data, so the test rows stay unseen. The notebook does this later, in the train/test section.

Linear regression, 5-fold CV on all 506 rows

Mean negative MSE ≈ −37.13, so the mean squared error is about 37. The minus sign comes only from the scoring name; the next chapter explains it. Not in the video: in price units, \(\sqrt{37} \approx 6.1\), a typical error of about $6,100.

To predict, call lin_regressor.predict(X_test) on the rows you want. The model has to be fitted first, which causes a small surprise later. Linear regression offers almost nothing to tune, so the next step is ridge, which fights overfitting, and lasso, which can also drop features. For the IIT Madras treatment of linear regression, see Part 10 (part-10.html); for K-fold cross-validation, see Part 11 (part-11.html).

Ridge regression, tuned with GridSearchCV

Two imports: Ridge from linear_model, and GridSearchCV from model_selection, the tool for hyperparameter tuning.

from sklearn.linear_model import Ridge
from sklearn.model_selection import GridSearchCV

He opens the Ridge documentation to see what can be tuned. alpha is the strength of the penalty: the multiplier on the sum of squared slopes in the theory, and the most useful parameter to tune. max_iter caps how many times an iterative solver may update the coefficients. It could be tuned too, but he concentrates on alpha.

\[ J(\theta) = \frac{1}{m}\sum_{i=1}^{m}\big(h_\theta(x_i) - y_i\big)^2 + \alpha\sum_{j=1}^{n}\theta_j^2 \]

Not in the video: scikit-learn's Ridge minimizes \(\lVert y - Xw\rVert^2 + \alpha\lVert w\rVert^2\), the sum of squared errors rather than the mean, and it never penalizes the intercept.

The candidate values go in a dictionary that maps the parameter's name to a list. He first types C, then corrects himself: C belongs to logistic regression, and ridge calls it alpha. The list runs from tiny values, where ridge is almost plain linear regression, up to 20. GridSearchCV takes the estimator, the grid and the scoring rule (Shift+Tab shows the signature), plus cv for the number of folds.

Cell · ridge grid search
ridge = Ridge()
parameters = {'alpha': [1e-15, 1e-10, 1e-8, 1e-3, 1e-2, 1, 5, 10, 20]}
ridge_regressor = GridSearchCV(ridge, parameters, scoring='neg_mean_squared_error', cv=5)
ridge_regressor.fit(X, y)

print(ridge_regressor.best_params_)   # {'alpha': 20}
print(ridge_regressor.best_score_)    # about -32

The captions give the first value as 1e-5, but the long run of zeros he reads out fits 1e-15. Either way it is effectively α = 0.

Grid search tries every value in the grid, or every combination when several parameters are listed. It scores each by cross-validation and keeps the best. His first run fails because he wrote the grid as a list instead of a dictionary; writing it as {'alpha': [...]} fixes it. He says errors are nothing to worry about: read them and fix them.

The result is α = 20 with a best score of about −32, against −37.13 for linear regression. Because the score is a negative error, −32 is the better of the two: ridge helps.

Why the score is negative 2:33:54

He tells viewers not to worry about the sign: −37 and 37 describe the same error. scikit-learn offers neg_mean_squared_error as a scoring option, and root-mean-squared versions exist too (neg_root_mean_squared_error). His guess is that the library keeps its scoring generic so that other algorithms can share it. Not in the video: the documented rule is that every scikit-learn scorer is maximized. Errors are therefore negated, so the largest score is the smallest error.

With neg_mean_squared_error, a score closer to zero is better: −32 beats −37.13.

Lasso is the same code with one name changed. He copies the cell, imports Lasso and reuses the same grid:

from sklearn.linear_model import Lasso

lasso_regressor = GridSearchCV(lasso, parameters, scoring='neg_mean_squared_error', cv=5)

\[ J(\theta) = \frac{1}{m}\sum_{i=1}^{m}\big(h_\theta(x_i) - y_i\big)^2 + \alpha\sum_{j=1}^{n}\lvert\theta_j\rvert \]

Not in the video: scikit-learn's Lasso minimizes \(\frac{1}{2m}\lVert y - Xw\rVert^2 + \alpha\lVert w\rVert_1\). It divides the squared error by \(2m\) and Ridge does not, so the same α is a far stronger penalty in Lasso. That is one reason ridge settles on a large α and lasso on α = 1. Very small α values also make Lasso slow to converge, and it prints ConvergenceWarnings for them.

Reading the three scores live, he briefly gets the direction muddled and says ridge is not helping. He then lines them up: linear −37, ridge −32, lasso −35. Ridge is closest to zero, so it is the model to choose; lasso beats plain linear regression but not ridge. He also remarks that ridge is there to reduce overfitting and wavers again on whether it helps here; by the rule above, it does.

For the theory of both penalties, see Part 2 (krish-ml-02.html). For the IIT Madras treatment, see Part 12 (part-12.html).

\[ R^2 = 1 - \frac{\sum_i (y_i - \hat y_i)^2}{\sum_i (y_i - \bar y)^2} \]

He reminds viewers that R² should be as close to 1 (100%) as possible. Lasso reaches about 67%. Ridge gives about 68%. Linear regression first throws an error:

y_pred = ridge_regressor.predict(X_test)

Not in the video: cross_val_score trains copies of the estimator, one per fold, and leaves the original untouched, so lin_regressor had never been fitted. GridSearchCV is different: with its default refit=True it retrains the best model on all the data given to fit and keeps it, which is why its predict works.

The order of the arguments

r2_score expects the true values first: r2_score(y_true, y_pred). He passes them the other way round and says the order does not matter. It does. R² divides by the spread of its first argument, so swapping the arguments changes the number. For a least-squares fit the predictions vary less than the true prices, so the swapped version usually comes out lower than the true R².

r2_score(y_test, y_pred)              # the documented order: true values, then predictions

Adjusted R²

He looks for adjusted R² in sklearn.metrics and does not find it. Not in the video: scikit-learn has no function for it, but it is one line from R², the number of test rows \(m\) and the number of features \(p\):

\[ R^2_{\text{adj}} = 1 - (1 - R^2)\,\frac{m - 1}{m - p - 1} \]
m, p = X_test.shape                   # 167 rows, 13 features
adj_r2 = 1 - (1 - r2) * (m - 1) / (m - p - 1)

His conclusion on regression: a linear model fits a straight line (with 13 features, a flat hyperplane), so it cannot follow curved relationships and its score levels off. More flexible algorithms later in the video, such as XGBoost, can go further. R² and adjusted R² are explained in Part 1 (krish-ml-01.html).

Now the held-out rows. predict returns a 0 or a 1 for each of the 188 test rows, and three metrics from sklearn.metrics judge them:

The confusion matrix counts each combination of true class and predicted class. He says the order of the two arguments makes no difference except that the entries move. Swapping them transposes the matrix, so false positives and false negatives trade places; the diagonal stays put. Not in the video: scikit-learn's convention is confusion_matrix(y_true, y_pred), with a row for each true class and a column for each prediction.

\[ \text{accuracy} = \frac{TP + TN}{\text{all}}, \qquad \text{precision} = \frac{TP}{TP + FP}, \qquad \text{recall} = \frac{TP}{TP + FN} \] \[ F_1 = \frac{2 \cdot \text{precision} \cdot \text{recall}}{\text{precision} + \text{recall}} \]

The accuracy is about 96%. The classification report lists precision, recall and F1 for each class (plus the accuracy and averages), and because the classes are fairly balanced they all come out high. Key terms

Bunch
The dictionary-like object scikit-learn's loaders return; keys such as data, target and feature_names can also be read as attributes.
iloc
Position-based indexing in pandas: [rows, columns]. iloc[:, :-1] is all but the last column, iloc[:, -1] only the last.
Independent / dependent features
The inputs X (13 house features) and the output y (Price) the model predicts.
K-fold cross-validation
Cut the rows into K blocks; each block is the test set once while the others train. The K scores are averaged.
cross_val_score
Runs K-fold cross-validation for one model and returns the K scores. It fits copies, so the model itself stays unfitted.
neg_mean_squared_error
MSE with a minus sign, because scikit-learn scorers are maximized. Closer to zero is better.
Hyperparameter α
The penalty strength in Ridge and Lasso, set before training. Larger α shrinks the coefficients more.
GridSearchCV
Tries every value (or combination) in a parameter grid, scores each by cross-validation and refits the best.
best_params_ / best_score_
The winning grid entry and its mean cross-validation score.
train_test_split
Shuffles and splits the rows; test_size=0.33 keeps 33% aside for the final check.
R² score
\(1 - \text{SS}_{\text{res}}/\text{SS}_{\text{tot}}\); 1 is a perfect fit. Call it as r2_score(y_true, y_pred).
Adjusted R²
R² corrected for the number of features \(p\); not built into scikit-learn.
C (logistic regression)
Inverse regularization strength, about \(1/\lambda\). Small C means a strong penalty.
Confusion matrix
Counts of true class against predicted class; the diagonal holds the correct predictions.

Test yourself

Q1The DataFrame has 13 feature columns followed by Price. What do dataset.iloc[:, :-1] and dataset.iloc[:, -1] return?

The part before the comma selects rows and : means all of them. :-1 selects every column except the last, so the first is X, a 506 × 13 table of features. -1 selects only the last column, so the second is y, the 506 prices.

Q2Why did dataset.columns = df.target raise "Length mismatch: Expected axis has 13 elements, new values have 506 elements"?

A header needs one name per column, 13 of them. df.target holds one price per house, 506 values. The names are in df.feature_names; the prices belong in a new column, dataset['Price'] = df.target.

Q3You run 5-fold cross-validation on 100 records. How many models are trained, how large is each test block, and what does cross_val_score return?

Five models, one per fold. Each test block has 20 records and each training set 80. It returns five scores, one per fold; their mean is the cross-validation score.

Q4Linear regression scores −37.13 and ridge −29.9 with scoring='neg_mean_squared_error'. Which is better, and why are the numbers negative?

Ridge. The scores are negated MSEs, so −29.9 means an MSE of 29.9, smaller than 37.13. scikit-learn negates error measures because all its scorers are maximized; the highest score, closest to zero, is the smallest error.

Q5GridSearchCV runs over his wider grid of 14 α values with cv=5. How many fits does it perform, and what is best_score_?

14 × 5 = 70 cross-validation fits, plus one refit of the best α on all the data (with the default refit=True), so 71. best_score_ is the mean of the five fold scores for the best α, here a negative MSE.

Q6After cross_val_score(lin_regressor, ...), calling lin_regressor.predict(X_test) raises NotFittedError, yet ridge_regressor.predict(X_test) works. Why?

cross_val_score trains copies of the estimator and leaves the original untouched, so lin_regressor was never fitted; call lin_regressor.fit(X_train, y_train) first. GridSearchCV refits the best model on the data passed to fit and stores it, so it can predict straight away.

Q7Take y_test = [1, 2, 3, 4] and y_pred = [1.5, 2, 3, 3.5]. Compute r2_score(y_test, y_pred) and r2_score(y_pred, y_test). Does the order matter?

The squared errors sum to \(0.25 + 0 + 0 + 0.25 = 0.5\) either way. Around its mean 2.5, y_test has \(\sum(y - \bar y)^2 = 5\), so the correct R² is \(1 - 0.5/5 = 0.9\). y_pred has \(\sum = 1 + 0.25 + 0.25 + 1 = 2.5\), so the swapped call gives \(1 - 0.5/2.5 = 0.8\). The order matters: the true values must come first.

Q8The logistic model's test confusion matrix has 63 and 118 on the diagonal and 3 and 4 off it. What is the accuracy? And would raising C from 1 to 20 strengthen or weaken the regularization?

Accuracy = (63 + 118) / (63 + 118 + 3 + 4) = 181 / 188 ≈ 0.963, the 96% he reports. C is the inverse of the regularization strength, so a larger C means a weaker penalty.
