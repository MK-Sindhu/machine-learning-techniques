Ridge, Lasso and logistic regression

A line that passes through every training point can still fail on new data, so ridge and lasso regression add a penalty on the slopes, and lasso can also drop useless features. Logistic regression then squashes a line through a sigmoid to classify, is trained with log loss, and is judged with the confusion matrix, precision, recall and the F-beta score.

At a glance

  • Overfitting means good results on the training data and poor results on test data (Krish: low bias, high variance). Underfitting is poor on both. The goal is a generalized model that does well on both.
  • Ridge (L2) adds \(\lambda\,(\text{slope})^2\) to the squared-error cost, so steep lines cost more. Lasso (L1) adds \(\lambda\,|\text{slope}|\) and can also drop useless features. \(\lambda\) is a hyperparameter chosen by cross-validation.
  • A regression line on 0/1 labels is pulled around by outliers and gives outputs below 0 and above 1. Logistic regression squashes the line with the sigmoid \(g(z) = 1/(1 + e^{-z})\) and predicts 1 when \(z \ge 0\).
  • Squared error with a sigmoid inside is non-convex, so logistic regression uses log loss: \(-\log h_\theta(x)\) when \(y = 1\) and \(-\log(1 - h_\theta(x))\) when \(y = 0\), minimized by gradient descent.
  • On imbalanced data accuracy misleads. Precision \(= \frac{TP}{TP+FP}\) watches false positives, recall \(= \frac{TP}{TP+FN}\) watches false negatives, and \(F_\beta\) weighs the two: \(\beta < 1\) favours precision, \(\beta > 1\) favours recall.

Overfitting and underfitting

The chapter starts from the linear regression cost function of Part 1, the average squared gap between prediction and truth:

\[ J(\theta_0, \theta_1) = \frac{1}{2m}\sum_{i=1}^{m}\big(h_\theta(x^{(i)}) - y^{(i)}\big)^2, \qquad h_\theta(x) = \theta_0 + \theta_1 x \]

Now take a training set of just two points. The best-fit line passes through both, so every error is zero and \(J = 0\). To keep the picture simple Krish lets the line pass through the origin, so \(\theta_0 = 0\) and only the slope \(\theta_1\) is learnt.

Zero cost looks perfect, since gradient descent exists to make the cost small. Then new points arrive. The line's predictions for them can land far from their true values. This is overfitting: the model performs well on the training data and fails to perform well on the test data.

Krish attaches a word to each half. Doing well on the training data is low bias; doing badly on the test data is high variance. In his usage, bias always refers to the training data and variance to the test data.

Ridge regression: the L2 penalty

Write \(\hat y^{(i)}\) for the prediction \(h_\theta(x^{(i)})\). For the two-point line the sum of \((\hat y^{(i)} - y^{(i)})^2\) is zero, and that zero is the warning sign. Ridge regression, also called L2 regularization, adds one more term to the cost: \(\lambda\) times the square of the slope.

\[ J(\theta_1) = \sum_{i}\big(\hat y^{(i)} - y^{(i)}\big)^2 + \lambda\,\theta_1^2, \qquad \hat y = \theta_1 x \quad (\theta_0 = 0) \]

The cost can no longer drop to zero just by fitting the training points exactly, because a steep line now pays for its slope.

Worked example

Krish sets \(\lambda = 1\) and starts from the line through both points, which has slope 2. The errors are zero, so \(J = 0 + 1 \times 2^2 = 4\) (he first says 3, then corrects it). Gradient descent does not stop there, since 4 can still be lowered. It changes \(\theta_1\) and finds a flatter line. The training errors are now small but nonzero, and the penalty falls faster than they rise. With slope 1.5 the penalty is \(1.5^2 = 2.25\), so the cost is 2.25 plus a small error, which is below 4.

He leaves the "small error" unspecified. With the illustrative points \((1, 2)\) and \((2, 4)\), which lie on a line of slope 2, it is \((1.5 - 2)^2 + (3 - 4)^2 = 1.25,\) so \(J(1.5) = 3.5\).

Not in the video: setting \(\frac{dJ}{d\theta_1} = 10(\theta_1 - 2) + 2\lambda\theta_1\) to zero gives \(\theta_1 = \frac{10}{5 + \lambda}\) for these two points. A bigger \(\lambda\) gives a flatter line, and \(\lambda = 0\) gives back slope 2.

The penalty is about steepness. A very steep slope often goes with overfitting, so ridge keeps the line less steep while still following the data. The result sits closer to low bias and low variance, and new points end up nearer the line, as the blue line in the first figure shows.

Two hyperparameters

  • \(\lambda\) sets how strongly the penalty pushes the steepness down. It is a hyperparameter, chosen by hyperparameter tuning in the practical session (Part 3).
  • The number of iterations is how many times gradient descent updates \(\theta_1\): the convergence algorithm. After enough iterations the cost stops falling and settles at a small value, and he checks \(R^2\) or adjusted \(R^2\) as the iterations go on. The cost never reaches zero; if it did, the model would be overfitting again.

Not in the video: with several features the ridge penalty is \(\lambda(\theta_1^2 + \theta_2^2 + \dots + \theta_n^2)\), and the intercept \(\theta_0\) is normally left out of it. A very large \(\lambda\) flattens the line so much that the model underfits.

Lasso regression: the L1 penalty and feature selection

Lasso regression, or L1 regularization, keeps the squared-error term and replaces the squared slope by its absolute value (Krish says "mod of the slope"):

\[ J(\theta_1) = \sum_{i}\big(\hat y^{(i)} - y^{(i)}\big)^2 + \lambda\,|\theta_1| \]

Lasso also prevents overfitting. Its second use is feature selection. With many features the prediction is

\[ \hat y = \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \dots + \theta_n x_n \]

so there is one slope per feature, and the penalty covers all of them. For a feature that plays no real part in predicting the output, the coefficient becomes very small, close to zero, which amounts to dropping that feature. His reason for the difference from ridge: squaring makes the penalty grow quickly, while the absolute value does not, so lasso ends up neglecting the features that are not important.

Correction: he writes the penalty as \(|\theta_0 + \theta_1 + \dots + \theta_n|\), the absolute value of a sum. The L1 penalty is the sum of absolute values, \(\lambda(|\theta_1| + |\theta_2| + \dots + |\theta_n|)\), again usually without \(\theta_0\).

Not in the video: why lasso gives exact zeros

Minimizing squared error plus a penalty is the same as minimizing the squared error inside a region around the origin. For ridge the region is a disc; for lasso it is a diamond with its corners on the axes. Points of equal squared error form ellipses around the unpenalized solution \(\hat\theta\), and the answer is where the first ellipse touches the region. The diamond's corners stick out, so the touch often happens at a corner, where one coefficient is exactly 0. The disc has no corners, so ridge shrinks every coefficient without setting any to zero.

Choosing λ, and the two penalties side by side

\(\lambda\) is found by cross-validation: train the model with several values of \(\lambda\), evaluate each one, and keep the value that performs best. Throughout, the aim is to reduce the cost without it ever reaching zero; how far it falls depends on \(\lambda\) and the slopes. His practical advice is to try both penalties and use whichever gives the better performance metric.

Assumptions of linear regression

Before moving to classification, Krish lists what helps linear regression work well.

  1. Normally distributed features. The model trains well when the features follow a normal (Gaussian) distribution. If a feature does not, apply feature transformation: a mathematical function applied to the data to bring it closer to normal.
  2. Standardization. Scale each feature with the z-score, \(z = (x - \mu)/\sigma\), so it has mean 0 and standard deviation 1 (the standard scaler). Wherever gradient descent is involved this helps: with small, comparable values, training reaches the global minimum quickly, while very large values stretch the cost surface and slow it down. It is optional; he recommends it because it cuts training time.
  3. Linearity. The model gives good answers when the relationship in the data is linear. He notes that logistic regression shares this property.
  4. No multicollinearity. If two inputs, say \(x_1\) and \(x_2\), are 95% correlated with each other, keeping both adds little. Drop one and keep the other. The variance inflation factor (VIF) is the usual check, and he promises a separate video on it. He also names homoscedasticity as one more assumption.

Not in the video: the classical normality assumption concerns the residuals \(y - \hat y\), so making skewed features more normal is a practical habit more than a formal requirement. VIF for feature \(j\) is \(1/(1 - R_j^2)\), where \(R_j^2\) comes from regressing \(x_j\) on the other features; values above about 5 to 10 are a common warning sign. Homoscedasticity means the errors have the same spread for all inputs.

Classification, and why a regression line falls short

Logistic regression is the first classification algorithm in the video. The example: from a student's hours of study and hours of play, predict pass or fail. There are two fixed categories, so this is binary classification, where logistic regression works very well. Asked whether it can handle more than two classes, Krish says yes.

Not in the video: the usual routes to more classes are one-vs-rest (one binary model per class) and the softmax version of logistic regression.

Keep one feature, hours of study from 1 to 7. Students who studied less than 3 hours failed and those who studied more passed. Encode fail as 0 and pass as 1.

First attempt: a regression line with a 0.5 cut-off

Fit an ordinary best-fit line through the 0/1 points and compare its output with 0.5, halfway between the classes:

\[ \text{predict } 0 \text{ (fail) if } h_\theta(x) < 0.5, \qquad \text{predict } 1 \text{ (pass) if } h_\theta(x) \ge 0.5 \]

A new student whose point on the line reads 0.25 is predicted to fail; one further right reads above 0.5 and is predicted to pass. So far it works.

Two problems

  1. An outlier moves the line. Add a student who studied 9 or 10 hours and passed. The least-squares line tilts to reach that point, so the place where it crosses 0.5 moves right. Students who really passed now get outputs below 0.5 and are predicted to fail.
  2. Outputs leave the range 0 to 1. The line rises above 1 on the right and, extended to the left, drops below 0. For two classes coded 0 and 1 the output should stay between 0 and 1.

The fix is to squash the line at both ends so its output stays between 0 and 1. That is the job of the sigmoid.

1:40:12 1:42:50 the formula 1:43:56 the 0.5 rule

Squashing the line: the sigmoid

With \(n\) features the linear part is written compactly as

\[ \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \dots + \theta_n x_n = \theta^\top x \]

Not in the video: for \(\theta^\top x\) to include \(\theta_0\), the vector \(x\) gets an extra first entry \(x_0 = 1\).

Logistic regression applies a function \(g\) on top of the line. With one feature, let \(z = \theta_0 + \theta_1 x\). Then

\[ h_\theta(x) = g(z) = \frac{1}{1 + e^{-z}} = \frac{1}{1 + e^{-(\theta_0 + \theta_1 x)}} \]

\(g\) is the sigmoid, or logistic function. Its graph is an S-shaped curve that rises from 0 to 1 and crosses 0.5 at \(z = 0\). That gives the classification rule:

The 0.5 rule \[ g(z) \ge 0.5 \iff z \ge 0 \;\Rightarrow\; \text{predict } 1, \qquad g(z) < 0.5 \iff z < 0 \;\Rightarrow\; \text{predict } 0 \]

Not in the video: the decision boundary is where \(\theta^\top x = 0\). With one feature it is a single cut-off value of \(x\); with two features it is a straight line.

The name joins the two steps: a regression line, then the logistic (sigmoid) squash. Asked whether squashing also helps with the outlier problem, Krish says it does.

For the IIT Madras treatment, see Part 15 (part-15.html), which motivates the sigmoid as a probability model.

The cost function: from squared error to log loss

The training set is \(\{(x^{(1)}, y^{(1)}), \dots, (x^{(m)}, y^{(m)})\}\) with every \(y^{(i)} \in \{0, 1\}\). For simplicity Krish again sets \(\theta_0 = 0\), so \(z = \theta_1 x\) and the only parameter to learn is \(\theta_1\).

Squared error does not work

The first idea is to keep the linear regression cost and only swap in the sigmoid:

\[ J(\theta_1) = \frac{1}{m}\sum_{i=1}^{m}\frac12\big(h_\theta(x^{(i)}) - y^{(i)}\big)^2, \qquad h_\theta(x) = \frac{1}{1 + e^{-\theta_1 x}} \]

With a straight-line \(h_\theta\) this cost is a convex bowl, a parabola with one minimum that gradient descent always reaches. With the sigmoid inside it becomes non-convex: the curve has several dips, the local minima. The slope is zero at each of them, so \(\theta_1\) stops being updated and gradient descent can get stuck there without ever reaching the global minimum.

Log loss

The cost used instead treats the two labels separately:

\[ \text{Cost}\big(h_\theta(x), y\big) = \begin{cases} -\log h_\theta(x) & \text{if } y = 1 \\ -\log\big(1 - h_\theta(x)\big) & \text{if } y = 0 \end{cases} \]
  • \(y = 1\): the cost is 0 when \(h_\theta(x) = 1\) and grows as \(h_\theta(x)\) moves towards 0.
  • \(y = 0\): the cost is 0 when \(h_\theta(x) = 0\) and grows as \(h_\theta(x)\) moves towards 1.

Because of the log, the combined cost is convex, so gradient descent can always reach the global minimum. The two cases also fit in one line:

\[ \text{Cost}\big(h_\theta(x), y\big) = -\,y\log h_\theta(x) - (1 - y)\log\big(1 - h_\theta(x)\big) \]

Check it: with \(y = 1\) the second term has the factor \(1 - 1 = 0\) and vanishes, leaving \(-\log h_\theta(x)\). With \(y = 0\) the first term vanishes, leaving \(-\log(1 - h_\theta(x))\). Averaging over the training set gives the cost function of logistic regression.

Logistic regression cost (log loss) \[ J(\theta_1) = -\frac{1}{m}\sum_{i=1}^{m}\Big[\,y^{(i)}\log h_\theta(x^{(i)}) + \big(1 - y^{(i)}\big)\log\big(1 - h_\theta(x^{(i)})\big)\Big], \qquad h_\theta(x) = \frac{1}{1 + e^{-\theta_1 x}} \]

He writes the factor in front as \(\frac{1}{2m}\), carried over from linear regression; the usual form has \(\frac1m\). A constant factor does not move the minimum. He also says the cost function and loss function are almost the same thing. Not in the video: the loss is usually the error on one example and the cost its average over the training set.

1:57:55

The convergence algorithm

Training is the same gradient descent loop as for linear regression, run on the log-loss cost.

  1. Gradient descent for logistic regression
  2. Start from some value of \(\theta\) and pick a learning rate \(\alpha\).
  3. Repeat until convergence: \(\theta_j := \theta_j - \alpha\,\frac{\partial J(\theta)}{\partial \theta_j}\), for every \(j\) (here only \(\theta_1\)).
  4. \(J\) is the log loss above, with \(h_\theta(x) = 1/(1 + e^{-\theta^\top x})\).

Not in the video: the derivative works out to \(\frac{\partial J}{\partial \theta_j} = \frac1m\sum_i \big(h_\theta(x^{(i)}) - y^{(i)}\big)\,x_j^{(i)}\). It has the same form as linear regression's gradient, though \(h_\theta\) is now the sigmoid.

Asked whether this cost is the log-likelihood from probability, he says yes.

Not in the video: if \(P(y = 1 \mid x) = h_\theta(x)\), then \(J\) is the negative average log-likelihood of the labels, so minimizing log loss is maximum likelihood estimation. See Part 15 (part-15.html) for the derivation and the gradient.

Imbalanced data: when accuracy misleads

Suppose the output column has 900 zeros and 100 ones. That is imbalanced data, which he also calls biased data. A 600 / 400 split is close enough to balanced for most algorithms. A strong imbalance, on the other hand, affects most of the algorithms in the video.

Now take a model that ignores its input and always predicts 0. It is right on all 900 zeros:

\[ \text{Accuracy} = \frac{900}{1000} = 90\% \]

That looks like a good score from a model that never finds a single positive. So accuracy alone cannot be trusted. Oversampling the smaller class can help in some cases; the main remedy is to choose performance metrics that look at the errors directly: precision, recall and the F-score.

Precision and recall

Definitions \[ \text{Recall} = \frac{TP}{TP + FN}, \qquad \text{Precision} = \frac{TP}{TP + FP} \]

Recall asks: of all the actual positives, how many did the model predict as positive? It is about false negatives, which should be reduced. Recall is also called the true positive rate or sensitivity.

Precision asks: of all the predicted positives, how many are actually positive? It is about false positives.

Which one matters?

ProblemMetricError to reduceReason
Spam detectionPrecisionFalse positivesHe picks precision, which gives false positives priority. Not in the video: a false positive is a genuine mail sent to the spam folder, where it may never be read.
Does a patient have cancer?RecallFalse negativesTelling a patient who has cancer that they do not is the dangerous case. A false alarm leads to further tests, which will clear it up.
Will the stock market crash tomorrow?Depends on who the model is forBothPeople want to be warned so they can sell, while for companies a false alarm is very bad. When both kinds of error matter, use the F-score.

The F-beta score

Krish deliberately says F-score rather than F1 score, because the general version has a parameter \(\beta\) that decides the balance between precision \(P\) and recall \(R\):

F-beta score \[ F_\beta = \frac{(1 + \beta^2)\,P\,R}{\beta^2 P + R} \]
Choice of \(\beta\)Use it whenFormula
\(\beta = 1\)False positives and false negatives matter equally\(F_1 = 2PR/(P + R)\)
\(\beta < 1\), e.g. 0.5False positives matter more\(F_{0.5} = 1.25\,PR/(0.25\,P + R)\)
\(\beta > 1\), e.g. 2False negatives matter more\(F_2 = 5\,PR/(4P + R)\)

\(F_1\) is the harmonic mean of precision and recall, the same shape as \(2xy/(x + y)\). Substituting \(\beta = 1\), he first writes \(1 + 4\) for \(1 + \beta^2\) and then corrects it to \(1 + 1\).

For his seven-point example (\(P = 0.60\), \(R = 0.75\)) this gives \(F_1 \approx 0.67\), \(F_{0.5} = 0.625\) and \(F_2 \approx 0.71\). These values are worked out for these notes.

Key terms

Overfitting
Good results on the training data, poor results on test data. Krish's labels: low bias, high variance.
Underfitting
Poor results on both training and test data. Krish labels it high bias, high variance.
Generalized model
Good on both training and test data: low bias, low variance. The goal.
Ridge regression (L2)
Adds \(\lambda\sum\theta_j^2\) to the squared-error cost, so steep slopes are penalized.
Lasso regression (L1)
Adds \(\lambda\sum|\theta_j|\); prevents overfitting and selects features by driving unhelpful coefficients to zero.
\(\lambda\) (lambda)
Hyperparameter that sets how strong the penalty is; chosen by cross-validation.
Cross-validation
Training and evaluating the model with several candidate \(\lambda\) values to pick the best one.
Multicollinearity
Features that are highly correlated with each other. Keep one of them; check with the variance inflation factor.
Sigmoid (logistic) function
\(g(z) = 1/(1 + e^{-z})\). Squashes any number into the range 0 to 1, with \(g(0) = 0.5\).
Log loss
\(-y\log h_\theta(x) - (1 - y)\log(1 - h_\theta(x))\): the convex cost of logistic regression.
Confusion matrix
The 2 × 2 table of true positives, false positives, false negatives and true negatives.
Precision
\(TP/(TP + FP)\): the share of predicted positives that are actually positive.
Recall
\(TP/(TP + FN)\): the share of actual positives that are found. Also sensitivity or true positive rate.

\((1 + \beta^2)PR/(\beta^2P + R)\). \(\beta = 1\) gives F1; \(\beta < 1\) favours precision, \(\beta > 1\) favours recall.

Test yourself

Q1A model scores 95% on its training data and 70% on test data. Which case is this, and how would Krish label its bias and variance?

Overfitting: it does well on the training data and badly on new data. In his terms that is low bias (training) and high variance (test). Ridge or lasso regularization is his remedy for a linear model.

Q2Training points \((1, 2)\) and \((2, 4)\), a line through the origin and \(\lambda = 2\). Compute the ridge cost \(\sum(\hat y - y)^2 + \lambda\theta_1^2\) at \(\theta_1 = 2\) and at \(\theta_1 = 1.5\). Which slope does ridge prefer?

At \(\theta_1 = 2\) the errors are 0 and the penalty is \(2 \times 4 = 8\), so \(J = 8\). At \(\theta_1 = 1.5\) the errors are \((1.5 - 2)^2 + (3 - 4)^2 = 1.25\) and the penalty is \(2 \times 2.25 = 4.5\), so \(J = 5.75\). Ridge prefers the flatter line. The exact minimum is at \(\theta_1 = 10/(5 + 2) \approx 1.43\).

Q3Why can lasso remove a feature completely while ridge only shrinks it?

Krish's answer: the absolute value does not grow like the square, and the coefficients of unhelpful features end up near zero, so those features are neglected. The geometric reason (not in the video): the L1 region is a diamond with corners on the axes, and the loss contours often first touch it at a corner, where a coefficient is exactly 0. The L2 disc has no corners. Put another way, the L1 penalty keeps pulling with the same strength \(\lambda\) all the way to zero, while the ridge pull \(2\lambda\theta_j\) fades as \(\theta_j\) gets small.

Q4Give two reasons not to classify pass/fail with a linear regression line and a 0.5 cut-off.

First, a single outlier (a pass at 10 hours, say) tilts the line, moves its 0.5 crossing, and makes some true passes come out below 0.5. Second, the line's output goes above 1 and below 0, although the classes are coded 0 and 1. The sigmoid fixes both by squashing the output into the range 0 to 1.

Q5A logistic model has \(z = -6 + 2 \times \text{hours}\). What does it predict for 2 hours and for 4 hours of study, and where is the decision boundary?

2 hours: \(z = -2\), \(g = 1/(1 + e^{2}) \approx 0.12 < 0.5\), so fail. 4 hours: \(z = 2\), \(g = 1/(1 + e^{-2}) \approx 0.88\), so pass. The boundary is where \(z = 0\), at 3 hours.

Q6With natural logs, what is the log loss of one example with \(y = 1\) when \(h_\theta(x) = 0.9\), and when \(h_\theta(x) = 0.1\)?

\(-\ln 0.9 \approx 0.105\) and \(-\ln 0.1 \approx 2.303\). A confident wrong prediction costs about 22 times as much as a confident right one, and the cost grows without limit as \(h_\theta(x) \to 0\).

Q7A classifier has TP = 40, FP = 10, FN = 20, TN = 930. Compute accuracy, precision, recall and F1.

Accuracy \(= 970/1000 = 0.97\). Precision \(= 40/50 = 0.80\). Recall \(= 40/60 \approx 0.667\). \(F_1 = 2(0.80)(0.667)/(0.80 + 0.667) \approx 0.727\). The 97% accuracy hides that a third of the actual positives are missed.

Q8Which metric, and which side of \(\beta = 1\), would you pick for cancer screening? For a spam filter?

Cancer screening: recall, because a missed cancer (false negative) is the dangerous error, so \(\beta > 1\), for example \(F_2\). Spam filter: precision, because the error to avoid is the false positive, so \(\beta < 1\), for example \(F_{0.5}\).
